## 10. Calibrating the judge rubrics (product slice 10)

The method: run the judge set ten times; collect each graded run with the states that Jev saw and the scores it gave; add runs that are bad by construction (negative controls), so that the data holds a known "no"; ask Opus the same question over the same state and record yes, no or ambiguous; then find, for each rubric and not for each case, the threshold at which Jev agrees best with Opus. Decisions: (a) Opus sees exactly the state of each rubric, because the rubrics see different views of a run and a disagreement must come from the judge and not from its input; (b) the controls are made from the collected records, so they cost no CLI run, and they are scored by Jev and by Opus like any other record, which also measures the reference: Opus must reject them; (c) the commands are small and separate (`collect`, `controls`, `jev`, `opus`, `analyze`), each reads and writes the one JSON file, `~/jev-calibration-transcripts.json`, and each can be run again without repeating a paid call; (d) the analysis recommends and changes nothing: the threshold in the config and the weight of a rubric are the user's decision; (e) none of it runs from `pnpm test`, from CI or from the `eval` script.
